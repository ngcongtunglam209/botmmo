Tích hợp bán hàng.

Một hướng dẫn đầy đủ để đồng bộ sản phẩm, tạo đơn an toàn và giao tài khoản tự động qua Lâm Shop Partner API.

01 — QUICKSTART

Chạy request đầu tiên trong 60 giây

Dùng endpoint /api/v2/me để kiểm tra API key, tên đối tác, số dư ví và trạng thái bảo trì trước khi tạo đơn.

Terminal
curl "https://api.example.com/api/v2/me" \
  -H "x-api-key: API_KEY_CUA_BAN"
✓
Response thành công{ "ok": true, "data": { "partner_name": "ShopA", "balance": 850000 } }
02 — AUTHENTICATION

Một API key cho toàn bộ request

Gửi key qua header x-api-key. Không đặt key trong URL, JavaScript phía trình duyệt, log công khai hoặc repository.

KHUYẾN NGHỊ

x-api-key

x-api-key: API_KEY_CUA_BAN
HỖ TRỢ

Bearer token

Authorization: Bearer API_KEY_CUA_BAN

Tạo đơn sản phẩm thường

06 — DELIVERY

Đọc đúng dữ liệu để giao khách

CÓ data.items

Giao ngay

Mỗi phần tử là một tài khoản hoặc item. delivered_count cho biết số lượng đã giao.

CHƯA CÓ ITEMS

Poll trạng thái

Lưu order_code, gọi endpoint chi tiết mỗi 5–15 giây đến khi có items hoặc trạng thái cuối.

!
Đừng nhầm data.link

Với API V2, nội dung giao hàng nằm trong data.items. data.link thường chỉ mô tả cách giao. Chỉ endpoint legacy /api/buy dùng link làm nội dung chính.

08 — IDEMPOTENCY

Retry mà không tạo đơn thứ hai

Dùng cùng một giá trị cho body và header. Nếu timeout, gửi lại nguyên request với nguyên mã — không sinh mã mới.

HEADERx-idempotency-key: ORDER_20260727_0001
=
BODY"partner_ref": "ORDER_20260727_0001"

Request lặp hợp lệ trả đơn cũ với data.idempotent_replay: true.

09 — ERRORS

Mã lỗi và cách xử lý

400

Field thiếu/sai, idempotency không khớp

Sửa request, không retry nguyên trạng
401 / 403

Key sai, bị tắt hoặc IP không được phép

Kiểm tra cấu hình và liên hệ admin
402

Không đủ số dư ví API

Nạp thêm số dư rồi tạo đơn mới
404

Không thấy sản phẩm hoặc đơn

Đồng bộ catalog / kiểm tra mã đơn
409

Thiếu stock hoặc mã đơn đang xử lý

Chờ rồi tra cứu theo partner_ref
422

JSON sai kiểu dữ liệu

Đối chiếu schema trong API Reference
429

Vượt giới hạn request/phút

Đọc Retry-After và backoff
502 / 503

Nguồn ngoài lỗi hoặc hệ thống bảo trì

Retry có backoff, giữ nguyên idempotency key
10 — CODE EXAMPLES

Mẫu client tối thiểu

client.js
const BASE_URL = "https://api.example.com";
const API_KEY = process.env.LAMSHOP_API_KEY;

async function request(path, options = {}) {
  const response = await fetch(BASE_URL + path, {
    ...options,
    headers: {
      "Content-Type": "application/json",
      "x-api-key": API_KEY,
      ...options.headers
    }
  });
  const body = await response.json();
  if (!response.ok) throw new Error(JSON.stringify(body));
  return body;
}
client.py
import os
import requests

BASE_URL = "https://api.example.com"
API_KEY = os.environ["LAMSHOP_API_KEY"]

def request(method, path, **kwargs):
    response = requests.request(
        method, BASE_URL + path,
        headers={"x-api-key": API_KEY},
        timeout=30, **kwargs
    )
    response.raise_for_status()
    return response.json()

<?php
